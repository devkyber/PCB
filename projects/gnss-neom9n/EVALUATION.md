## ERC result

**0 errors**, 45 warnings — all in the expected/harmless categories per §15.7: 25 `endpoint_off_grid`, 20 `pin_to_pin` (both artifacts of EasyEDA-converted symbols losing KiCad's electrical pin-type metadata). Every net was wired via `ed.get_pin_position()` at the symbol's real pin coordinate — no hand-guessed label positions. `PWR_FLAG` markers added on VCC/GND since the fetched LDO symbol doesn't carry proper power-output pin typing.

Every NEO-M9N-00B pin is accounted for (24/24): wired, or given an explicit no-connect with a documented reason (USB unused, LNA_EN no external LNA in V1, Reserved pins per datasheet). SAFEBOOT_N and EXTINT — both flagged as commonly-missed on GNSS breakouts — are wired with a pull-up and broken out respectively.

## DRC result

**1 error, 27 warnings, 33 unconnected items** (`--refill-zones`).

The 1 error: `starved_thermal` — the U.FL connector's split shield pad (J2 pad 2, two physically separate copper regions sharing one pad number) gets only 1 ground-zone thermal spoke where KiCad's default rule wants 2. This is a zone-fill/thermal-relief setting nuance caused by the pad's split geometry, not a clearance or short — trivially fixed in the KiCad GUI by setting that pad's zone-connection to "solid" instead of "thermal relief."

The 27 warnings are all cosmetic: silkscreen reference designators overlapping copper/pads/board edge (`silk_over_copper` x11, `silk_overlap` x9, `silk_edge_clearance` x3 — the board is small and densely packed, several ref-des labels need manual nudging in the GUI) and `lib_footprint_mismatch` x3 (fetched/embedded footprint copies differ slightly from the system library copies for U.FL, and the two `PinHeader` footprints — cosmetic library-link warning, not a geometry error).

33 unconnected items is expected: **this is a placement pass, not a routed board** — kicad-cli 10 dropped Specctra DSN export from the CLI, so Freerouting can't be driven headlessly from this non-interactive session. Every pad has its correct net assigned (parsed directly from the ERC-verified schematic script); routing is deferred to KiCad's GUI (manual or GUI DSN export + Freerouting).

### Fixed during layout iteration (documented per §15.7 — "expected, not broken")
Two iterations of real DRC fixes were needed once real footprint geometry replaced first-guess coordinates:
- Generic `PinHeader_1xNN_Vertical` footprints anchor at **pin 1**, not their geometric center, and — confirmed by reading absolute pad coordinates out of the generated file — KiCad's rotation-90° convention for this footprint spreads pads in **+X**, not the assumed −X. J3/J4 were originally placed running off the board edge; both are now correctly inset with margin.
- The CR1220 holder's courtyard (read from its `.kicad_mod` F.CrtYd layer: 13.1mm × 4.3mm) is far larger than its 2-pad SMD footprint suggests — it collided with the VCC decoupling caps until moved clear.
- A generic tactile-switch footprint (`SW_Push_1P1T_NO_CK_PTS125Sx43SMTR`, the RESET_N button) proved too large to fit anywhere near the module's right edge without colliding with 5+ neighboring parts. **It was dropped from the PCB placement** (still present in the schematic, ERC-clean) — RESET_N remains fully functional via the R3 pull-up + TP2 test point (jumper TP2 to GND to reset). Documented as a known simplification, not silently omitted.

## RF trace impedance (§15.5)

Target: 50Ω single-ended microstrip for the RF_IN trace (module pin 11 → J2 U.FL antenna connector).

Per docs/DESIGN_RULES.md §15.5 reference table: on standard JLCPCB 2-layer stackup (1.6mm FR4 core, 1oz/35µm copper, top layer over solid ground plane, εr≈4.5), 50Ω microstrip ≈ **2.85mm trace width**.

**Caveat**: 2.85mm is unusually wide for a GNSS RF trace and reflects the *standard* 1.6mm JLCPCB stackup, not an RF-optimized one — most production GNSS boards (including SparkFun's) use a thinner top dielectric (0.2–0.4mm prepreg to the first ground layer, often via a 4-layer stackup) to get a more routable ~0.3–0.4mm 50Ω trace. **Recommendation for the routing phase**: either (a) request JLCPCB's controlled-impedance service with a thinner top-layer dielectric and recompute, or (b) accept the 2.85mm width on the standard 1.6mm 2-layer stackup used here — it is fully routable given the antenna connector's proximity to the module in this layout (<10mm). This board was **not routed** in this pass (placement only), so the trace does not yet exist to measure; the width is a target for whoever routes it, and should be entered into the KiCad net class before routing (the `RF_50ohm` net class in `gnss-neom9n.kicad_pro` currently defaults to 0.3mm — **must be corrected to match the chosen stackup calculation before routing**).

Ground plane clearance: the F.Cu/B.Cu ground pour is pulled back with a rectangular notch (board-edge bite, x≥22mm, y=9–16mm in layout space) covering the RF_IN/VCC_RF pins and the full antenna-connector corridor — well over the checklist's 2mm minimum pull-back (checklist item #18).

## Known gaps / limitations (honest accounting)

1. **Not routed.** This is a placement pass only — kicad-cli 10 has no CLI Specctra DSN export, so headless Freerouting isn't possible from this non-interactive session. Every pad has a correct net assignment ready for routing in the KiCad GUI.
2. **RESET_N push-button dropped from the PCB** (kept in schematic only) — see DRC section above. RESET_N is still fully controllable via TP2.
3. **RF trace width is a target, not a routed measurement** — 2.85mm per the standard-stackup calculation in docs/DESIGN_RULES.md §15.5; should be re-verified against JLCPCB's actual controlled-impedance calculator for the final chosen stackup before ordering, and the `RF_50ohm` net class in the `.kicad_pro` updated to match.
4. **Antenna keepout notch was sized from the checklist minimum + component geometry, not cross-checked against u-blox's exact published keepout dimension** (Integration Manual PDF wasn't machine-readable in this session).
5. **LNA_EN left unconnected (NC)** — this V1 assumes a passive antenna using the module's internal LNA. If an active (powered) antenna is wanted later, LNA_EN and a VCC_RF bias-tee path would need adding — a real, if modest, rev2 change.
6. **Cosmetic silkscreen overlaps (27 DRC warnings)** — reference designators need manual nudging in the KiCad GUI on this dense a board; none are functional/copper issues.
7. **Board grew from the ~25×25mm target to 34×40mm** to fit a real CR1220 holder + U.FL connector + two breakout headers without violating any real component's courtyard — documented as a deliberate, DRC-driven decision rather than an oversized/unjustified board (component density remains reasonable given the module alone is 16×12.2mm plus a battery holder with an unusually generous mechanical courtyard).
